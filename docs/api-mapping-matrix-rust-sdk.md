# Public API mapping — Kupferdraht ↔ matrix-rust-sdk

ADR-0009 commits Kupferdraht to a public API shaped after matrix-rust-sdk.
This document is the contract enforcement mechanism: every public
symbol exposed from `kupferdraht-core` (and the UniFFI bindings derived
from it) is listed here with its matrix-rust-sdk equivalent.

## How to use this document

- **Adding a new public symbol** (a new method on `Client`, a new
  type re-exported from `lib.rs`, etc.): add a row to the relevant
  table below. If the new symbol has no direct matrix-rust-sdk
  equivalent, it must be in the **Wire-specific extensions** section
  with an explicit justification.
- **Modifying a public symbol's signature**: update the row.
- **Reviewing a PR**: any new `pub` in a `client/`, `rooms/`,
  `timeline/`, `sync/`, `encryption/`, or `storage/` symbol that
  isn't reflected here is a review defect, not a follow-up task.

The mapping is enforced socially, not by tooling. A future
`cargo public-api` snapshot may automate drift detection (see
`PLAN.md` open questions); for now this hand-maintained doc is the
single source of truth.

---

## Status legend

- **1:1** — The Kupferdraht symbol matches matrix-rust-sdk exactly in
  name and shape (modulo type-system differences like `&str` instead
  of `&UserId`).
- **Aligned** — Same intent, slightly different signature (e.g.
  `Option<String>` vs `Option<&UserId>`); difference documented in
  the row.
- **Wire extension** — No matrix-rust-sdk equivalent; exists because
  the Wire backend exposes a concept Matrix doesn't.
- **Drift** — Differs from matrix-rust-sdk for a Kupferdraht-specific
  reason (legacy, ergonomics, threat model). Each drift carries an
  explicit justification.

## ClientBuilder

| Kupferdraht symbol                                          | matrix-rust-sdk equivalent                                                          | Status | Notes |
|---|---|---|---|
| `ClientBuilder::new()`                                 | `Client::builder()`                                                                  | Aligned | matrix-rust-sdk's builder is reached through `Client::builder`; Kupferdraht exposes the type directly. Same pattern. |
| `ClientBuilder::server(ServerConfig)`                  | `ClientBuilder::homeserver_url(Url)`                                                 | Wire extension | Wire pairs HTTPS API host + separate WebSocket host (`ServerConfig` carries both). matrix-rust-sdk's single-URL model doesn't fit. |
| `ClientBuilder::base_dir(PathBuf)`                     | `ClientBuilder::sqlite_store(path, passphrase)`                                      | Aligned | The persistence root. Kupferdraht opens the per-account `base_dir/accounts/<id>/{kupferdraht.db, mls.db}` (the default `StorageProvider`); matrix-rust-sdk opens its `StateStore` / `CryptoStore` under the path. |
| `ClientBuilder::storage_provider(Arc<dyn StorageProvider>)` | (none — matrix-rust-sdk has no pluggable store-factory seam)                    | Wire extension | Inject a consumer storage backend (e.g. a cloud-bot server). The provider opens **ready** stores (`open_global` + `open_store`); the concrete store owns its encryption (no key in the trait). `mls.db` stays SDK/SQLite for now. |
| `ClientBuilder::permit_http()`                         | (none — matrix-rust-sdk's `ClientBuilder::homeserver_url` parses `Url` and accepts http+https alike) | Wire extension | Kupferdraht enforces `https://` by default; the opt-in is strictly for `httpmock`-backed integration tests. |
| `ClientBuilder::account(account_id: impl Into<String>)` | (none — matrix-rust-sdk's `Client` holds one implicit session, no by-id account selection) | Kupferdraht-specific | Selects which persisted account `ClientBuilder::resume` reconstructs. Required for `resume`; registry-driven callers use `Kupferdraht::resume(account_id)` instead, which sets this internally. |
| `ClientBuilder::device_label(label: impl Into<String>)` | `LoginBuilder::initial_device_display_name(name)` | Aligned | Both label the device at auth time (Step 41; shown in Wire's / Matrix's device list). matrix-rust-sdk sets it via a chained method on the login-request builder; Kupferdraht sets it on `ClientBuilder` before `login`/`register`. When unset, a platform default ("Kupferdraht (iOS)", …) is used. |
| `ClientBuilder::login(email, password, 2fa) -> Arc<PendingLogin>` | `Client::login_username(...).send()` (post-build)                              | Aligned (two-phase) | matrix-rust-sdk does login on `Client`; Kupferdraht does it on `ClientBuilder`. Two-phase since Step 24: `login` authenticates → `PendingLogin`, `register_device` materializes the `Client` (see the Step-24 rows below). |
| `ClientBuilder::initiate_sso(code, success_redirect, error_redirect) -> String` (Step 17β) | `Client::login_sso(\|url\| async {…})` (redirect closure) | Wire extension | Validates the SSO code (`HEAD /sso/initiate-login/{code}`) and returns the SP-driven initiate URL the consumer opens in a browser. Wire's SP-side flow differs from matrix-rust-sdk's redirect-closure model; finalise via `finalize_sso` (17b). |
| `ClientBuilder::initiate_sso_by_email(email, success_redirect, error_redirect) -> String` (Step 17β) | `Client::login_sso` (SDK resolves the IdP) | Wire extension | Resolves the backend's **default** SSO code (`GET /sso/settings`) — Wire v14 has no per-email-domain discovery, so the team default is used for every email; multi-IdP backends must call `initiate_sso` with an explicit code. |
| `ClientBuilder::finalize_sso(sso_cookie) -> Arc<PendingLogin>` (Step 17β) | (part of `Client::login_sso` — the closure returns and login proceeds) | Wire extension | Completes SSO login from the `zuid` cookie: mints the first access token (`POST /access`, no `client_id`), fetches `/self`, and returns a `PendingLogin` (`password: None`). Converges with the password flow at the shared post-auth assembly; `register_device` runs phase 2 unchanged. |
| `ClientBuilder::register(name, email, password) -> Arc<PendingClient>` | `Client::register(request) -> Session`                                                     | Pending — Step 16 | matrix-rust-sdk returns a session directly; Kupferdraht splits register from activation because Wire requires a separate `POST /activate` step (email-delivered code). Builder shape consistent with `login`. The `PendingClient` intermediate has no matrix analog — it's a Wire-extension recording the "registered but not yet activated" state. See `docs/plan/archive/16-account-registration.md`. |
| `ClientBuilder::activate(email, code, password) -> Arc<Client>` | (no analog — Matrix has no two-step register) | Wire extension | Process-symmetric counterpart to `PendingClient::activate`, for callers that lost the in-memory `PendingClient` handle (e.g. a separate `kupferdraht-cli activate` invocation after `kupferdraht-cli register`). Runs `POST /activate` then the existing `login` → `register_device` pipeline, returning a ready `Arc<Client>` directly — same shape as `login`/`resume`. The originally-planned single-shot `register_and_activate(name, email, password, code)` variant never shipped; `activate` covers the "I already have the code" use case instead. |
| `PendingClient::activate(code) -> Arc<Client>` | (no analog — Wire-extension)                                                                | Pending — Step 16 (Wire extension) | Kupferdraht-specific intermediate handle for the register→activate transition. Holds the pending account's user_id + email; no MLS state, no session token until `activate` completes (which returns a ready `Arc<Client>`). |
| `Kupferdraht::register(server, name, email, password) -> PendingAccount` | (no analog — Matrix has no device-level multi-account manager) | Wire extension | Manager-level registration: reuses the manager's base_dir / keystore / provider wiring. Unlike `ClientBuilder::register` (the registry-less CLI path), the returned handle is registry-aware. |
| `PendingAccount::activate(code) -> Arc<Client>` | (no analog — Wire-extension)                                  | Wire extension | Manager-aware twin of `PendingClient::activate`: on success it additionally writes the device-registry `AccountEntry` (marked active) and persists the session — the same writes `Kupferdraht::login` makes, so the account is immediately listable and resumable. |
| `Kupferdraht::initiate_sso(server, code, success_redirect, error_redirect) -> String` (Step 17β) | (no analog — Matrix has no device-level manager; SSO via `Client::login_sso`) | Wire extension | Manager-level twin of `ClientBuilder::initiate_sso`, reusing the manager's server / permit-http wiring. FFI-mirrored (`ffi::Kupferdraht`, wasm `initiateSso`). Finalise via `finalize_sso` (17b). |
| `Kupferdraht::initiate_sso_by_email(server, email, success_redirect, error_redirect) -> String` (Step 17β) | (no analog — device-level manager) | Wire extension | Manager-level twin of `ClientBuilder::initiate_sso_by_email`; team-default code via `GET /sso/settings`. FFI-mirrored (`ffi::Kupferdraht`, wasm `initiateSsoByEmail`). |
| `Kupferdraht::finalize_sso(server, sso_cookie, device_label?) -> Arc<PendingLogin>` (Step 17β) | (no analog — device-level manager) | Wire extension | Manager-level twin of `ClientBuilder::finalize_sso`; on `register_device` it writes the device-registry row + persists the session (same as `Kupferdraht::login`). FFI-mirrored (`ffi::Kupferdraht`, wasm `finalizeSso`). |
| `Kupferdraht::login(server, email, password, 2fa, device_label?) -> Arc<PendingLogin>` (Step 24; `device_label` Step 41) | (no analog — Matrix has no per-user device cap) | Wire extension (two-phase) | Manager-level phase 1 (authenticate). Was a one-shot `-> Arc<Client>`; now returns `PendingLogin` so the per-user device cap is recoverable on the captured session. uniffi can't return "Client *or* recovery handle" from one call, so login always returns the handle and `register_device` returns the `Client`. |
| `PendingLogin::{register_device, devices, delete_device}` (Step 24) | (no analog — Matrix has no per-user device cap) | Wire extension | `register_device()` runs phase 2 → ready `Client` (single-use on success, `TooManyDevices` retryable). `devices()`/`delete_device(id)` free a slot via `GET`/`DELETE /clients` on the held login token. Manager-side handle like `PendingAccount`; auth-agnostic recovery (SSO-ready). |

## Kupferdraht (device manager)

`Kupferdraht` is the device-level entry point sitting above per-account
`Client`s (`manager/mod.rs`) — it owns the device-wide `GlobalStore`
registry, lists accounts for a picker, and builds/resumes the
per-account `Client`. matrix-rust-sdk has no equivalent: a
`matrix_sdk::Client` is a single implicit session, not a multi-account
manager, so every row below is a Wire/Kupferdraht extension. The
`Kupferdraht::{register, login, initiate_sso, initiate_sso_by_email,
finalize_sso}` terminal methods and `PendingAccount` / `PendingLogin`
are already covered in the `ClientBuilder` table above (they are the
manager-aware twins of the same-named `ClientBuilder` methods); this
table covers `Kupferdraht`'s own core surface plus `KupferdrahtBuilder`.

| Kupferdraht symbol                                          | matrix-rust-sdk equivalent                                                          | Status | Notes |
|---|---|---|---|
| `Kupferdraht::open(base_dir, keystore) -> Result<Self>`     | (no analog — Matrix has no device-level multi-account manager) | Wire extension | Opens the device manager with the shipped default `SqliteStorageProvider` (encrypted `global.db` registry + per-account stores). Thin wrapper over `Kupferdraht::builder().base_dir(..).keystore(..).build()`. |
| `Kupferdraht::builder() -> KupferdrahtBuilder`                   | (no analog)                                                                          | Wire extension | Entry point to inject a custom `StorageProvider` (e.g. a server-side backend for cloud bots). |
| `Kupferdraht::permit_http(self) -> Self`                    | (none — matrix-rust-sdk's `ClientBuilder::homeserver_url` accepts http+https alike)  | Wire extension | Post-construction twin of `KupferdrahtBuilder::permit_http()` / `ClientBuilder::permit_http()` — flows through to every `ClientBuilder` the manager builds internally. Test-only opt-in. |
| `Kupferdraht::accounts() -> Result<Vec<AccountEntry>>`      | (no analog — no device-level account registry)                                      | Wire extension | The device account registry, listable without unlocking any account. `AccountEntry { account_id, server, handle, display_name, last_active_ms }`. |
| `Kupferdraht::active_account() -> Result<Option<String>>`   | (no analog)                                                                          | Wire extension | The account id last marked active (written by `PendingLogin::register_device`, `Kupferdraht::resume`, or `PendingAccount::activate` — phase-1 `login` itself writes nothing), if any — picker-UI convenience. |
| `Kupferdraht::home_id() -> &str`                            | (no analog — matrix-rust-sdk has no installation id; its store is per session)      | Kupferdraht-specific | **Step 93 (ADR-0025).** The home's id: 32 lowercase hex in `base_dir/home.id`, created once under the home lock, read on every open. Every keystore id of the home (`kupferdraht.<home-id>.…`) and the login cookie label carry it, so two homes on one keystore never share an entry. FFI `Kupferdraht.home_id()`, wasm `Kupferdraht.homeId`. |
| `Kupferdraht::cookie_label() -> String`                     | (no analog — Matrix has no per-`(user, label)` refresh-cookie slot)                  | Kupferdraht-specific | **Step 93.** The Wire login cookie label of this home, `kupferdraht-<home-id>` (replaces the Step-41 per-install label that lived in the keystore); recorded in `SessionRecord.cookie_label` at login. FFI `Kupferdraht.cookie_label()`, wasm `Kupferdraht.cookieLabel`. |
| `Kupferdraht::resume(account_id: &str) -> Result<Arc<Client>>` | `Client::restore_session` (single-account)                                        | Aligned | Manager-aware resume: validates `account_id` against the registry, reuses a still-live cached `Client` for the account if one exists (Step 39 — at most one live `Client` per account), otherwise rebuilds via `ClientBuilder::account(id).resume()`. |
| `KupferdrahtBuilder::base_dir(PathBuf) -> Self`             | `ClientBuilder::sqlite_store(path, passphrase)` (per-account analog)                | Aligned | The persistence root (required). Hosts `global.db` and the per-account `accounts/<id>/` directories. |
| `KupferdrahtBuilder::keystore(Arc<dyn SecureKeyStore>) -> Self` | (none)                                                                          | Kupferdraht-specific | The platform keystore (required). The only place the manager hands out the keystore; the default provider self-fetches its keys per account. |
| `KupferdrahtBuilder::storage_provider(Arc<dyn StorageProvider>) -> Self` | (none — matrix-rust-sdk has no pluggable store-factory seam)               | Wire extension | Overrides the storage backend (global + per-account stores). Defaults to the shipped `SqliteStorageProvider` rooted at `base_dir`. |
| `KupferdrahtBuilder::permit_http() -> Self`                 | (none)                                                                               | Wire extension | Builder-time twin of `Kupferdraht::permit_http()`; either spelling works, `build()` reads the same flag. |
| `KupferdrahtBuilder::build() -> Result<Kupferdraht>`             | (no analog)                                                                          | Wire extension | Requires `base_dir` + `keystore` (`InvalidInput` otherwise); opens the device-level registry via the (default or injected) provider. |

## Identity

`kupferdraht::UserId` (Step 19, `identity/mod.rs`) is the one shipped typed
identifier — a validated newtype, not the soft-wrapper family the
original Step 15 plan proposed (rejected; see the Open Questions
section). matrix-rust-sdk equivalent: `ruma::OwnedUserId` /
`ruma::UserId`.

| Kupferdraht symbol                       | matrix-rust-sdk equivalent | Status | Notes |
|---|---|---|---|
| `UserId::new(localpart, domain) -> Self` | `UserId::parse(format!("@{localpart}:{domain}"))` (infallible construction has no direct ruma equivalent) | Drift | Infallible from already-separated parts the caller has checked; non-empty/no-`@` preconditions are `debug_assert!`-ed, not runtime-checked. Parts from runtime data go through `from_parts` (Step 95c). **Step 80:** ids that become path components are additionally refused at the materialization sites (`open_default_store` / `open_mls_provider`), so an unchecked `new` from server data can no longer reach `base/accounts/<id>`. |
| `UserId::from_parts(localpart, domain) -> Result<Self, KupferdrahtError>` | `UserId::parse(format!("@{localpart}:{domain}"))` | Drift | Step 95c: the checked form of `new` for parts that come from runtime data (event JSON, mentions, backend responses) — `InvalidInput` when a part is empty or contains `@`. Path safety stays `parse`'s stricter layer. |
| `UserId::parse(&str) -> Result<Self, KupferdrahtError>` | `ruma::UserId::parse(&str) -> Result<OwnedUserId, IdParseError>` | Aligned | Both validate a flat id string. Kupferdraht's rule is Wire-shaped (exactly one `@`, non-empty localpart + domain, and — Step 80 — both parts free of path metacharacters: `/`, `\`, `..`, control chars; the id is joined into the on-disk account layout). ruma's is Matrix-sigil-shaped (`@localpart:domain`). Same "parse untrusted input" contract. |
| `UserId::localpart() -> &str`       | `UserId::localpart() -> &str`                                                        | 1:1 | Same accessor, same meaning (the Wire user UUID, not further validated as a UUID by this type). |
| `UserId::domain() -> &str`          | `UserId::server_name() -> &ServerName`                                               | Aligned | matrix-rust-sdk's domain is itself a validated `ServerName` type; Kupferdraht's is a plain `&str`. Always present — no `Option`, unlike a bare/qualified split. |
| `UserId::as_str() -> &str`          | `UserId::as_str() -> &str`                                                           | 1:1 | The canonical qualified string. |

### Resync (Step 7e)

| Kupferdraht symbol                                              | matrix-rust-sdk equivalent                            | Status   | Notes |
|---|---|---|---|
| `Client::resync_existing_rooms() async -> Result<ResyncSummary>` | (no direct analog — Olm/Megolm has no per-device MLS leaf to go stale the same way) | Wire extension | Walks every cached room and re-joins (drop stale local MLS leaf + external-commit rejoin) any whose persisted leaf belongs to a prior `device_id` of the same `user_id` — the failure mode that surfaces after an interactive re-`login` (CHANGELOG.md §29). Per-room failures land in `ResyncSummary::failed` rather than aborting the whole walk. |
| `Client::resync_room(room_id: &str) async -> Result<()>` | (no direct analog)                                    | Wire extension | Per-room primitive driven by `resync_existing_rooms`: drop the stale local MLS group state for one room and re-join via external commit (reuses the unchanged `Client::join_room` path). |
| `ResyncSummary { attempted, already_current, resynced, failed: Vec<(String, String)> }` | (no direct analog — no equivalent "device changed under an existing session" repair concept) | Wire extension | Outcome of `resync_existing_rooms`: `attempted` (rooms inspected, including ones with no local MLS state), `already_current` (leaf already matches this device — no work), `resynced` (successfully rejoined), `failed` (per-room `(room_id, error_text)` pairs so the CLI can print a diagnostic line per entry). |

## Open questions

- **Typed identifiers (`UserId`, `DeviceId`, `RoomId`, …).**
  ~~Open question~~ → **Rejected** (CHANGELOG.md §49,
  2026-05-22). The originally-planned `kupferdraht::ids::{UserId,
  RoomId, DeviceId, MessageId, QualifiedUserId}` soft-wrapper
  family (newtype around `String`, no parse validation —
  CHANGELOG.md §43) was scrapped: it delivered type-tagging
  without format validation (a half-measure against the user's
  stated preference for call-site-visible invariants), and cost
  five new public types for steps that didn't need them.
  **`kupferdraht::ids` does not exist** — do not cite it. What
  shipped from the original Step 15 instead was a minimal
  owned-`String` → `&str` ergonomics pass on four signatures
  (`Client::room`, `Client::room_or_load`,
  `MessagesOptions::before`, `Timeline::redact`) plus a clearer
  parse-error message; `docs/plan/archive/15-typed-identifiers.md`
  is retained superseded, pointing here.
  A single **validated** typed id did ship later, out of this
  question's original scope: `kupferdraht::UserId` (Step 19,
  `identity/mod.rs`) — see the `## Identity` section above. No
  typed `RoomId` / `DeviceId` / `MessageId` exists; `Room::id()`,
  `Client::device_id()`, and message ids all stay `&str`/`String`.
- **`cargo public-api` snapshot.** Hand-maintained mapping is
  brittle. A future cycle may add a CI check via `cargo public-api`
  that snapshots `lib.rs`'s public symbols and fails on
  unreviewed drift.
- **Account live refresh.** Kupferdraht's `Account` is a snapshot;
  matrix-rust-sdk's is async-fetched lazily. Add `Account::fetch()`
  when the use case appears (probably after Step 2 when we
  implement self-update via `/v14/self` PUT semantics).
