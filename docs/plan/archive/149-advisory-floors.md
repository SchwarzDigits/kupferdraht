## Problem

A one-off sweep of the published repository advisories of every GitHub
repository behind `Cargo.lock` (251 repositories, 2026-11-06; Step 148's
phase 1) found four advisories that apply to the locked versions and
that neither RustSec nor GitHub's reviewed database carries
(`gh api /advisories/<id>` → 404), so `cargo deny` and Dependabot stayed
silent:

| Advisory | Severity | Locked | Fixed in | Path into the build |
|---|---|---|---|---|
| GHSA-7fx9-626j-vqph — `#[derive(ULE)]` (zerovec-derive) and `impl ULE for [T; N]` (zerovec) validate only the first element of a multi-element buffer | high | zerovec 0.11.6, zerovec-derive 0.11.3 | zerovec 0.11.8, zerovec-derive 0.11.5 (icu4x PRs 8393, 8400) | reqwest → cookie_store / url → idna → icu |
| GHSA-jh2m-fhpj-3vr7 — rustix's `Buffer`-based xattr getters take a zero-size query's count as initialised bytes (Linux) | high | rustix 1.1.4 | 1.1.6 (changes `src/fs/xattr.rs`; the advisory names no patched version) | tempfile → prost-build (build), uniffi_bindgen, dev-dependencies |
| GHSA-3jjw-63vg-v3hh — `normalize_utf8` / `split_normalized_utf8` can return invalid UTF-8 | low | icu_normalizer 2.2.0 | 2.4.0 (icu4x 2.4 CHANGELOG, unicode-org#8628; the advisory's patched field holds a range) | idna |
| GHSA-6pp4-4cxf-xf88 — quinn-udp's Unix `recv_single` fallback loops on a truncated datagram | high | quinn-udp 0.5.14 | 0.5.16 | none: in `Cargo.lock` as reqwest's optional HTTP/3 stack, never compiled |

Kupferdraht calls none of these crates directly. Whether a path through
idna or tempfile reaches an affected function was not traced; the fix
does not depend on it.

## Scope

1. `cargo update -p zerovec -p zerovec-derive -p rustix -p icu_normalizer
   -p quinn-udp` on the pinned 1.98 toolchain: 16 packages move within
   SemVer (the icu family to 2.4.0, tinystr, writeable, yoke, zerotrie),
   `synstructure` 0.14.0 is added (yoke-derive). No manifest change: the
   crates are transitive, so their floor lives in `Cargo.lock`; a Rust
   consumer's own lockfile takes the fixed versions with `cargo update`,
   which the CHANGELOG entry says.
2. A pin test reads the floors from `Cargo.lock`, one per crate with its
   advisory, like `step_142_openmls_0_9_2_pins`.
3. `THIRD-PARTY-NOTICES` and `docs/THIRD_PARTY_LICENSES.html`
   (regenerated by cargo-about; only the moved versions and
   `synstructure` 0.14.0 change). The notices also still named
   sqlite-remote-vfs and sqlite-remote-protocol 0.5.0, which Step 140
   moved to 0.6.0; corrected with them.
4. `CHANGELOG.md` `[Unreleased]` → Security.
